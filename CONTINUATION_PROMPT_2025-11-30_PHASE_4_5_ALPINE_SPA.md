#!/usr/bin/env ruby
# Demo script for Alpine.js SPA generation

puts "🎯 Generating Alpine.js SPA Demo..."
puts ""

# Check if test data exists
lur_path = 'spec/fixtures/packages/plateau_all.lur'
unless File.exist?(lur_path)
  puts "❌ Error: LUR package not found at #{lur_path}"
  puts "   Please ensure test fixtures are available"
  exit 1
end

# Generate with Alpine.js template (default)
puts "📦 Using LUR: #{lur_path}"
puts "⚙️  Config: examples/ShapeChangeConfig_Plateau_uro.xml"
puts "🎨 Template: Alpine.js (default)"
puts ""

workflow = Lutaml::Klin::Application::ProcessingWorkflow.new(
  progress_callback: ->(stage, msg) { puts "[#{stage}] #{msg}" }
)

result = workflow.execute(
  lur_path: lur_path,
  lxr_path: nil, # Will be auto-created from config
  config_path: 'examples/ShapeChangeConfig_Plateau_uro.xml',
  package_filter: '**::uro',
  output_dir: 'demo/output/alpine_spa',
  generate_mappings: true,
  generate_spa: true,
  spa_template_type: :alpine,  # Use Alpine.js template
  spa_data_mode: :embedded,     # Embedded for file:// access
  validate: true,
  verbose: true
)

puts ""
puts "=" * 70
puts "✅ Demo Generation Complete!"
puts "=" * 70
puts ""
puts "📊 Statistics:"
puts "   • Packages: #{result.total_packages}"
puts "   • Classes: #{result.resolved_classes}/#{result.total_classes}"
puts "   • Resolution Rate: #{result.resolution_rate.round(1)}%"
puts ""
puts "📁 Output:"
puts "   • SPA: demo/output/alpine_spa/spa/"
puts "   • Mappings: demo/output/alpine_spa/mappings/"
puts ""
puts "🌐 Open in Browser:"
spa_path = File.expand_path('demo/output/alpine_spa/spa/index.html')
puts "   file://#{spa_path}"
puts ""
puts "💡 Compare with vanilla JS:"
puts "   Run with --spa-template-type vanilla to see the difference"

=== SPA Template Types

LutaML Klin supports two SPA template types:

==== Alpine.js Template (Default)

The Alpine.js template provides a modern, reactive user interface with declarative components:

[source,bash]
----
lutaml-klin process \
  --lur model.lur \
  --lxr schemas.lxr \
  --config config.xml \
  --output output/ \
  --spa
----

Features:
- Declarative reactive components
- Smaller codebase (less code to maintain)
- Better performance with reactive updates
- Modern JavaScript patterns

==== Vanilla JavaScript Template

For environments without Alpine.js support or specific requirements:

[source,bash]
----
lutaml-klin process \
  --lur model.lur \
  --lxr schemas.lxr \
  --config config.xml \
  --output output/ \
  --spa \
  --spa-template-type vanilla
----

Features:
- No external dependencies
- Works in restricted environments
- Maximum browser compatibility
- Traditional JavaScript patterns

==== Data Modes

Both templates support two data modes:

**Embedded Mode** (default, works with file://):
[source,bash]
----
lutaml-klin process --lur model.lur --lxr schemas.lxr \
  --config config.xml --spa --spa-data-mode embedded
----

**Linked Mode** (requires HTTP server):
[source,bash]
----
lutaml-klin process --lur model.lur --lxr schemas.lxr \
  --config config.xml --spa --spa-data-mode linked
----
```

## Template Types

### Alpine.js Template (Recommended)

The Alpine.js template uses [Alpine.js](https://alpinejs.dev/) for reactive UI components.

**Advantages**:
- Declarative syntax (easier to read and maintain)
- Reactive updates (automatic UI synchronization)
- Smaller codebase (~300 lines vs ~700 lines)
- Modern JavaScript patterns
- Better performance for large datasets

**Architecture**:
- Single Alpine.js component (`mappingBrowser`)
- Reactive state management
- Computed properties for derived state
- Event-driven navigation
- Hash-based routing

**Usage**:
```ruby
workflow = Lutaml::Klin::Application::SpaWorkflow.new
workflow.generate_spa(
  schema_mapping,
  output_path,
  template_type: :alpine  # Default
)
```

### Vanilla JavaScript Template

The vanilla JavaScript template uses no external dependencies.

**Advantages**:
- Zero dependencies
- Maximum browser compatibility
- Works in restricted environments
- Traditional patterns (familiar to all developers)

**Architecture**:
- Class-based JavaScript
- Manual DOM manipulation
- Explicit state management
- Event listeners for interactivity

**Usage**:
```ruby
workflow = Lutaml::Klin::Application::SpaWorkflow.new
workflow.generate_spa(
  schema_mapping,
  output_path,
  template_type: :vanilla
)
```

## Template Selection Guidelines

**Choose Alpine.js when**:
- Building new SPAs (recommended default)
- Want modern reactive patterns
- Prefer declarative code
- Need better maintainability

**Choose Vanilla JS when**:
- External dependencies not allowed
- Maximum browser compatibility required
- Team unfamiliar with Alpine.js
- Integration with existing vanilla JS codebase

## Custom Templates

You can create custom templates by:
1. Creating a new directory in `lib/lutaml/klin/templates/`
2. Providing `index.html`, `assets/css/style.css`, `assets/js/app.js`
3. Using placeholders: `%<MAPPINGS_JSON>s`, `%<SEARCH_INDEX_JSON>s`, etc.
4. Registering in `SpaWorkflow::select_template_directory()`
```
