== Executive Summary

This document provides a unified plan for implementing lutaml-klin, the orchestration tool that bridges ShapeChange's UML-to-XSD transformations with Lutaml Model by generating machine-readable YAML mappings.

**Current Status**: Core implementation complete, Phase 8 (Type Override Mapping + Advanced Documentation) complete
**Goal**: Production-ready tool for PLATEAU UML-XML mapping generation
**Timeline**: 28-40 hours (3.5-5 work days) + 18 hours (Phase 8: advanced features and documentation)

=== Component Responsibilities

==== Input Components

**ShapeChange ConfigParser**::
* Parse ShapeChange XML configuration files
* Resolve XInclude references (HTTP and local)
* Extract encoding rules, type mappings, namespaces
* Output: ShapeChangeConfiguration model

**XmiNavigator**::
* Parse XMI files using lutaml-xmi
* Navigate UML package hierarchy
* Extract classes, attributes, associations
* Handle Enterprise Architect specifics
* Output: UML Package/Class/Attribute models

**XsdAnalyzer**::
* Parse XSD schemas using lutaml-xsd
* Extract element definitions
* Extract complex/simple type definitions
* Build lookup indexes for efficient matching
* Output: XSD Element/Type models

==== Processing Component

**MappingGenerator**::
* Coordinate all input sources
* Apply ShapeChange encoding rules
* Match UML classes to XSD types
* Match UML attributes to XSD elements/attributes
* Resolve namespace prefixes
* Handle inheritance and associations
* Output: Mapping models (Package/Class/Attribute)

==== Output Component

**YAML Serialization**::
* Use Lutaml::Model serialization
* Generate hierarchical YAML structure
* Support package nesting
* Support multiple output files

== Known Challenges

=== XMI Parsing

* Enterprise Architect XMI extensions
* Large file size (20MB+)
* Complex package hierarchies
* Multiple model versions

**Mitigation**: Use lutaml-xmi streaming if available, test incrementally

=== Encoding Rules

* Complex inheritance chains
* Context-dependent rules
* Multiple rule sets

**Mitigation**: Study reference documentation thoroughly, implement registry pattern

=== Type Matching

* Ambiguous type names
* Multiple namespaces
* Qualified vs unqualified names

**Mitigation**: Build comprehensive indexes, implement fuzzy matching fallback

=== XInclude Resolution

* HTTP resources may be unavailable
* Local paths vary by system
* Circular includes possible

**Mitigation**: Implement caching, use local mirrors, detect cycles

=== Format Principles

* **Hierarchical**: Preserves UML package structure
* **Namespace-aware**: Includes prefix and full namespace URI
