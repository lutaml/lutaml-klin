= YAML Mapping Output
:toc:
:toclevels: 3

== Overview

The YAML Mapping Output feature provides complete UML→XSD transformation traceability by automatically generating YAML mapping files alongside XSD schemas. These mapping files document every transformation decision, rule applied, and type resolution that occurred during XSD generation.

== Purpose

When generating XSD schemas from UML models, it's crucial to understand:

* Which UML classes map to which XSD elements/types
* Which UML attributes map to which XSD properties
* What transformation rules were applied
* What encoding decisions were made
* What type mappings were used

The YAML mapping output provides this complete traceability in a machine-readable and human-readable format.

== Architecture

=== Design Pattern: Observer Pattern

The implementation uses a passive observer pattern where `MappingCollector` observes XSD generation without interfering with the generation process:

[source]
----
XsdGenerator
    ↓
RuleProcessor → MappingCollector (observes)
    ↓
XSD Output + YAML Mapping Output
----

=== Key Components

==== MappingCollector

Location: `lib/lutaml/klin/shapechange/mapping_collector.rb`

Responsibilities:
* Passively observes transformation events
* Collects class-level and attribute-level mappings
* Aggregates transformation metadata
* Generates statistics
* Serializes to YAML via lutaml-model

==== TransformationInfo

Location: `lib/lutaml/klin/models/mapping/transformation_info.rb`

Stores metadata about transformations:
* Rules applied (array of rule IDs)
* Encoding rule used
* Type mapping source (XsdMapEntry, BasicType, SchemaRepository)
* Type mapping description
* Additional metadata (flexible hash)

==== Enhanced Mapping Models

Both `ClassMapping` and `AttributeMapping` models were enhanced with a `transformation_info` attribute to track transformation metadata.

== Usage

=== Basic Usage

[source,bash]
----
# Generate XSD with YAML mapping (default behavior)
lutaml-klin xsd \
  --lur model.lur \
  --config config.xml \
  --packages uro \
  --output out/

# Outputs:
#   out/urbanObject.xsd              (XSD schema)
#   out/urbanObject_mapping.yaml     (Mapping file)
----

=== Disabling YAML Generation

[source,bash]
----
# Disable YAML mapping generation
lutaml-klin xsd \
  --lur model.lur \
  --config config.xml \
  --packages uro \
  --output out/ \
  --no-generate-mapping
----

=== Programmatic Usage

[source,ruby]
----
require 'lutaml/klin'

# Load UML repository
uml_repository = Lutaml::Uml::UmlRepository.from_file('model.lur')

# Parse ShapeChange config
config = Lutaml::Klin::Shapechange::ConfigParser.parse_file('config.xml')

# Create generator with mapping enabled
generator = Lutaml::Klin::Shapechange::XsdGenerator.new(
  uml_repository,
  config,
  lur_path: 'model.lur',
  config_path: 'config.xml',
  generate_mapping: true  # default
)

# Generate schemas
results = generator.generate_schemas(['uro'], 'output/')

# Access mapping file path
mapping_file = results.first[:mapping_file]
----

== YAML Format

=== Structure

[source,yaml]
----
version: "1.0"                    # Mapping format version
generated_at: "2025-01-28T..."    # Generation timestamp
source_lur: "model.lur"           # Source LUR package
source_config: "config.xml"       # Source configuration

package_mappings:                 # Array of package mappings
  - uml_package_name: "uro"
    xsd_namespace: "https://..."
    xsd_namespace_prefix: "uro"
    
    class_mappings:               # Array of class mappings
      - uml_name: "Building"
        xsd_element_name: "Building"
        xsd_type_name: "BuildingType"
        
        transformation_info:      # Transformation metadata
          rules_applied:
            - "rule-xsd-cls-object-element"
            - "rule-xsd-cls-type"
          encoding_rule: "citygml"
          
        attribute_mappings:       # Array of attribute mappings
          - uml_name: "class"
            xsd_name: "class"
            xsd_type: "gml:CodeType"
            xsd_min_occurs: "0"
            xsd_max_occurs: "1"
            
            transformation_info:
              rules_applied:
                - "rule-xsd-prop-encode-properties"
              type_mapping_source: "XsdMapEntry"
              type_mapping_description: "CodeList → gml:CodeType"
----

=== Field Descriptions

==== Top Level

version:: Mapping format version (semantic versioning)
generated_at:: ISO 8601 timestamp of generation
source_lur:: Path to source LUR package
source_config:: Path to ShapeChange configuration
package_mappings:: Array of package-level mappings
namespaces:: Array of namespaces used

==== Package Mapping

uml_package_name:: UML package name
xsd_namespace:: Target XSD namespace URI
xsd_namespace_prefix:: Namespace prefix (e.g., "uro", "urf")
class_mappings:: Array of class-level mappings
created_at:: Package mapping creation timestamp
resolution_statistics:: YAML-serialized statistics

==== Class Mapping

uml_name:: UML class name
uml_qualified_name:: Fully qualified UML name
uml_stereotype:: UML stereotype (e.g., "FeatureType")
xsd_element_name:: Generated XSD element name
xsd_type_name:: Generated XSD type name
xsd_namespace:: Target namespace
transformation_info:: Transformation metadata (see below)
attribute_mappings:: Array of attribute-level mappings

==== Attribute Mapping

uml_name:: UML attribute name
uml_type:: UML attribute type
uml_multiplicity:: UML multiplicity (e.g., "0..1", "1..*")
xsd_name:: Generated XSD property name
xsd_type:: Generated XSD property type
xsd_min_occurs:: XSD minOccurs constraint
xsd_max_occurs:: XSD maxOccurs constraint
transformation_info:: Transformation metadata

==== Transformation Info

rules_applied:: Array of rule IDs applied (e.g., "rule-xsd-cls-object-element")
encoding_rule:: Encoding rule used (e.g., "citygml", "iso19136_2007")
type_mapping_source:: Source of type mapping:
  * "XsdMapEntry" - From ShapeChange XsdMapEntry
  * "BasicType" - From basic type processor
  * "SchemaRepository" - From LXR package
type_mapping_description:: Human-readable description (e.g., "CodeList → gml:CodeType")
metadata:: Additional metadata (YAML-serialized hash)

== Use Cases

=== 1. Traceability and Documentation

Use the YAML mapping to understand transformation decisions:

[source,bash]
----
# View all classes mapped
grep -A 3 "uml_name:" urbanObject_mapping.yaml

# Find which rule was applied to a class
grep -B 5 "rule-xsd-cls-object-element" urbanObject_mapping.yaml
----

=== 2. Validation and Quality Assurance

Verify transformations meet requirements:

[source,ruby]
----
require 'yaml'

mapping = YAML.load_file('urbanObject_mapping.yaml')

# Check all classes have transformations
mapping['package_mappings'].each do |pkg|
  pkg['class_mappings'].each do |cls|
    unless cls['transformation_info']
      puts "WARNING: #{cls['uml_name']} missing transformation info"
    end
  end
end

# Verify resolution success rate
stats = YAML.load(pkg['resolution_statistics'])
rate = stats['resolution_success_rate']
puts "Resolution success rate: #{(rate * 100).round(1)}%"
----

=== 3. Debugging Transformation Issues

When XSD generation doesn't produce expected results:

[source,bash]
----
# Find which rule was applied to problematic class
yq '.package_mappings[0].class_mappings[] | 
    select(.uml_name == "Building") | 
    .transformation_info.rules_applied' urbanObject_mapping.yaml

# Check type mappings
yq '.package_mappings[0].class_mappings[].attribute_mappings[] | 
    select(.xsd_type | contains("CodeType"))' urbanObject_mapping.yaml
----

=== 4. Generating Reports

Create transformation summary reports:

[source,ruby]
----
mapping = YAML.load_file('urbanObject_mapping.yaml')

# Count transformations by rule
rule_counts = Hash.new(0)
mapping['package_mappings'].each do |pkg|
  pkg['class_mappings'].each do |cls|
    cls['transformation_info']['rules_applied'].each do |rule|
      rule_counts[rule] += 1
    end
  end
end

puts "Transformation Rules Used:"
rule_counts.sort_by { |k, v| -v }.each do |rule, count|
  puts "  #{rule}: #{count} times"
end
----

== Performance Impact

=== Overhead

* **CPU**: <5% additional processing time
* **Memory**: Minimal (mappings collected incrementally)
* **Disk**: YAML files typically <3MB for 255 classes

=== Optimization

The implementation is optimized for minimal impact:

* Passive observation (no blocking)
* Incremental collection (no batch processing)
* Efficient serialization (lutaml-model)
* Optional (can be disabled with `--no-generate-mapping`)

== Limitations

=== Current Limitations

1. **Format Version**: Only version "1.0" currently supported
2. **Per-Package**: One YAML file per XSD file (not merged)
3. **No Reverse**: No XSD→UML mapping generation yet
4. **Statistics**: Basic statistics only (could be enhanced)

=== Future Enhancements

1. **Mapping Diff**: Compare mappings across versions
2. **Mapping Merge**: Combine multiple package mappings
3. **Mapping Validation**: Validate mapping completeness
4. **Enhanced Statistics**: More detailed metrics
5. **Reverse Mappings**: Generate UML from XSD with mapping
