= rule-xsd-cls-standard-gml-property-types

== Purpose

Generates standard GML property types following ISO 19136 conventions, including anonymous property types when needed for special encoding requirements.

== Background

GML 3.2 (ISO 19136) defines a standard pattern for property types that support both inline and by-reference encoding. This rule ensures properties follow GML conventions including:

* Standard PropertyType wrappers
* Association attribute groups (xlink:href, etc.)
* Ownership attributes (GML 3.2+)
* Anonymous types for special cases

== When It Applies

This rule applies to:

* Properties of feature types or object types
* Properties requiring association semantics
* Properties with special encoding requirements (nilReason, metadata, qualifiers)

== Implementation

Based on `XsdDocument.java:mapPropertyType()` and `addAnonymousPropertyType()` methods.

=== Three Property Type Patterns

==== Pattern A: By-Reference Encoding

Used when `inlineOrByReference="byreference"` or for code lists encoded as dictionaries.

.Anonymous type with gml:ReferenceType
[source,xml]
----
<element name="relatedBuilding">
  <complexType>
    <complexContent>
      <extension base="gml:ReferenceType"> <!--1-->
        <attribute name="nilReason" type="gml:NilReasonType"/> <!--2-->
      </extension>
    </complexContent>
  </complexType>
</element>
----
<1> Extends gml:ReferenceType for by-reference semantics
<2> Optional nilReason attribute if property allows it

==== Pattern B: Inline Encoding

Used when `inlineOrByReference="inline"` for embedded content only.

.Anonymous type with direct element reference
[source,xml]
----
<element name="component">
  <complexType>
    <sequence minOccurs="0"> <!--1-->
      <element ref="uro:Building"/> <!--2-->
    </sequence>
  </complexType>
</element>
----
<1> Optional sequence (minOccurs="0")
<2> Direct reference to target element

==== Pattern C: Standard InlineOrByReference

Default pattern supporting both inline and by-reference via xlink:href.

.Named PropertyType
[source,xml]
----
<complexType name="BuildingPropertyType"> <!--1-->
  <sequence minOccurs="0">
    <element ref="uro:Building"/>
  </sequence>
  <attributeGroup ref="gml:AssociationAttributeGroup"/> <!--2-->
  <attributeGroup ref="gml:OwnershipAttributeGroup"/> <!--3-->
</complexType>
----
<1> Named type following GML convention
<2> Standard association attributes (xlink:href, xlink:title, etc.)
<3> Ownership attributes (owned, nilReason) for GML 3.2+

.Anonymous type with special attributes
[source,xml]
----
<element name="building">
  <complexType>
    <sequence minOccurs="0">
      <element ref="uro:Building"/>
    </sequence>
    <attributeGroup ref="gml:AssociationAttributeGroup"/>
    <attributeGroup ref="gml:OwnershipAttributeGroup"/>
    <attribute name="nilReason" type="gml:NilReasonType"/> <!--1-->
    <attribute name="metadata" type="gml:reference"/> <!--2-->
  </complexType>
</element>
----
<1> Extra nilReason attribute for voidable properties
<2> Metadata attribute if property has metadata

== When Anonymous Types Are Generated

Anonymous property types are created instead of using standard PropertyType when:

1. **By-Reference Encoding**: `inlineOrByReference="byreference"`
2. **Code List Dictionary**: Code list with `asDictionary` flag
3. **NilReason Required**: Property has `nilReasonAllowed` or is `voidable`
4. **Metadata Attribute**: Property has metadata
5. **Qualifiers**: Property has qualifiers
6. **Array Properties**: GML array property pattern
7. **No Standard Type**: Value type has no PropertyType generated

== Decision Logic

The implementation follows this decision tree:

[source]
----
IF inlineOrByReference = "byreference" THEN
  → Pattern A (by-reference with gml:ReferenceType)
ELSE IF inlineOrByReference = "inline" THEN
  → Pattern B (inline-only sequence)
ELSE IF needs_special_attributes? THEN  // nilReason, metadata, qualifiers
  → Pattern C anonymous (full associations + special attrs)
ELSE IF should_use_property_type? THEN
  → Pattern C named (standard PropertyType)
ELSE
  → Direct type reference
END IF
----

== Notes

* Standard PropertyType names follow GML convention: `{ClassName}PropertyType`
* Association attributes enable by-reference encoding via xlink:href
* Ownership attributes are GML 3.2+ specific
* Anonymous types are generated inline within element declarations
* Pattern selection depends on multiple factors including encoding requirements
* NilReason attributes are separate from nillable (different purposes)
