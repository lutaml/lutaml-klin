= Rule: rule-xsd-cls-mixin-classes

== Overview

Process properties from mixin supertypes by including them in the class's sequence element. Mixin classes provide a way to achieve multiple inheritance in XML Schema which only supports single inheritance.

== Priority

Must-have (PLATEAU uses mixins extensively)

Description::
Due to XML Schema supporting only single inheritance (type derivation from a single base type, element substitutability restricted to a single element), multiple inheritance is not directly supported. However, for conceptual modelling, the ability to define abstract types which capture a set of properties associated with a concept is very convenient. The mixin pattern provides a solution.

== Java Implementation

Source:: [`XsdDocument.java:pComplexType`](lines 938-945) and [`XsdDocument.java:addMixinProperties`](lines 1121-1135)

=== Algorithm

The Java implementation follows this process:

==== In pComplexType:

. Check if class matches [`rule-xsd-cls-sequence`] (creates sequence element)
. Check if class matches [`rule-xsd-cls-mixin-classes`]
. If class matches [`rule-xsd-cls-mixin-classes-as-group`]:
  * Call [`addGroupReferences()`] to add group references
. Else:
  * Call [`addMixinProperties()`] to inline mixin properties

==== In addMixinProperties (Recursive):

. Get supertypes of the class
. For each supertype:
  * Check if supertype is a MIXIN
  * OR if supertype is abstract and matches [`rule-xsd-cls-no-abstract-classes`]
  * If match found:
    ** Call [`processLocalProperties()`] to add supertype's properties
    ** Recursively call [`addMixinProperties()`] on the supertype
. This flattens the mixin hierarchy into the class's property sequence

private void addMixinProperties(ClassInfo ci, Element e,
                                 SchematronSchema schDoc) {
    SortedSet<String> st = ci.supertypes();
    if (st != null && ci.matches("rule-xsd-cls-mixin-classes") &&
        !ci.matches("rule-xsd-cls-mixin-classes-as-group")) {
        for (String sid : st) {
            ClassInfo cix = model.classById(sid);
            if (cix != null && (cix.category() == Options.MIXIN ||
                (cix.matches("rule-xsd-cls-no-abstract-classes") &&
                 cix.isAbstract()))) {
                processLocalProperties(cix, e, schDoc);
                addMixinProperties(cix, e, schDoc);
            }
        }
    }
}

=== Design Principles

. Recursive property flattening from mixin hierarchy
. Supports both inline properties and group references
. Handles abstract classes as mixins
. Maintains property order

=== Implementation Details

The [`MixinClassesProcessor`] class extends [`BaseRuleProcessor`] and:

. Identifies mixin supertypes of a class
. Recursively processes mixin properties
. Adds properties from each mixin to the class's sequence
. Supports both direct property inclusion and group references
. Handles abstract classes that match [`rule-xsd-cls-no-abstract-classes`]

=== Test Case 1: Simple mixin inclusion

Input UML::
[source]
----
«mixin» Identifiable
  property id: String [1]
  property name: String [0..1]

class Building extends Identifiable
  property floors: Integer [1]
----

Expected XSD::
[source,xml]
----
<complexType name="BuildingType">
  <sequence>
    <!-- Mixin properties added first -->
    <element name="id" type="string"/>
    <element name="name" type="string" minOccurs="0"/>
    <!-- Own properties follow -->
    <element name="floors" type="integer"/>
  </sequence>
</complexType>
