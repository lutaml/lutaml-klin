= Rule: rule-xsd-prop-nillable

== Overview

Adds `nillable="true"` attribute to property elements when the property is voidable, allowing the property to have no value (nil) in XML instances.

== Priority

Must-have (PLATEAU uses extensively for optional properties)

== ShapeChange Documentation

Source:: `/Users/mulgogi/src/external/ShapeChange/shapechange-app/src/docs/asciidoc/targets/xml schema/General_Conversion_Rules.adoc`

Description::
When a property is marked as voidable in the UML model, the corresponding XML Schema element should allow nil values through the `nillable` attribute.

== Java Implementation

Source:: [`XsdDocument.java:addProperty`](lines 2240-2243)

=== Algorithm

The Java implementation is straightforward:

. Check if property has `voidable()` set to true
. Check if property matches [`rule-xsd-prop-nillable`]
. If both conditions are met, add `nillable="true"` attribute to the element
. Alternative trigger: `nilReasonAllowed()` with [`rule-xsd-prop-nilReasonAllowed`]

=== Implementation Logic

[source,java]
----
if ((pi.nilReasonAllowed() && pi.matches("rule-xsd-prop-nilReasonAllowed"))
        || (pi.voidable() && pi.matches("rule-xsd-prop-nillable"))) {
    addAttribute(e1, "nillable", "true");
}
----

== Notes

* `nillable="true"` allows `<element xsi:nil="true"/>` in XML instances
* Different from `minOccurs="0"` which allows element to be omitted entirely
* Voidable properties can have nil value even when required (`minOccurs="1"`)
* The nillable attribute applies to elements, not attributes
