= rule-xsd-cls-basictype-list

== Purpose

Encodes basic types with a single property having maxOccurs > 1 as list-based simpleTypes with length restrictions.

== Background

Basic types that contain a single property with multiplicity [n..*] should be encoded as XSD list types rather than as complex types with sequences. This provides a more compact and natural representation for homogeneous value lists.

== When It Applies

This rule applies when all of the following are true:

* Class has `«basicType»` stereotype
* Class has exactly one property
* Property has upper multiplicity > 1 (`maxOccurs > 1`)
* Property has `{sequence}` constraint (ordered)

== Implementation

Based on `XsdDocument.java:pAnonymousBasicType()` lines 1395-1468.

=== Algorithm

When processing a basic type class:

1. Check if class has exactly one property
2. Check if property multiplicity allows multiple values (`maxOccurs > 1`)
3. Check if property is ordered (has `{sequence}` constraint)
4. Determine the item type from property's value type
5. Map the item type to XSD simple type
6. Create `<xs:simpleType>` with nested `<xs:list>`
7. Add length restrictions based on multiplicity:
   * If multiplicity is `[n..n]` → use `<xs:length value="n"/>`
   * If multiplicity is `[min..*]` → use `<xs:minLength value="min"/>`
   * If multiplicity is `[min..max]` → use both `<xs:minLength>` and `<xs:maxLength>`

=== Syntax Definition

[source,xml]
----
<xs:simpleType name="{TypeName}"> <!--1-->
  <xs:restriction>
    <xs:simpleType>
      <xs:list itemType="{itemType}"/> <!--2-->
    </xs:simpleType>
    <xs:length value="{n}"/> <!--3-->
    <!-- or -->
    <xs:minLength value="{min}"/> <!--4-->
    <xs:maxLength value="{max}"/> <!--5-->
  </xs:restriction>
</xs:simpleType>
----
<1> Named type for the basic type class
<2> List with item type mapped from property type
<3> Exact length for [n..n] multiplicity
<4> Minimum length for [min..*] or [min..max]
<5> Maximum length for [min..max]

Where,

`{TypeName}`:: Name of the basic type class with "Type" suffix
`{itemType}`:: XSD simple type mapped from property's value type
`{n}`:: Exact cardinality for fixed-length lists
`{min}`:: Minimum cardinality
`{max}`:: Maximum cardinality

== Examples

=== Example 1: Fixed-Length List

.UML Model
[example]
====
[source]
----
«basicType» TransformationMatrix2x2
  └─ property list: Real [4] {sequence}
----
====

.Generated XSD
[example]
====
[source,xml]
----
<xs:simpleType name="TransformationMatrix2x2Type">
  <xs:restriction>
    <xs:simpleType>
      <list itemType="double"/>
    </xs:simpleType>
    <length value="4"/>
  </xs:restriction>
</xs:simpleType>
----
====

=== Example 2: Variable-Length List with Minimum

.UML Model
[example]

====

.Generated XSD
[example]

<xs:simpleType name="CoordinateListType">
  <xs:restriction>
    <xs:simpleType>
      <list itemType="double"/>

----
====

=== Example 3: Bounded-Length List

.UML Model
[example]
====
[source]
----
«basicType» SmallNumberList
  └─ property values: Integer [2..5] {sequence}
----
====

.Generated XSD
[example]
====
[source,xml]
----
<xs:simpleType name="SmallNumberListType">
  <xs:restriction>

----
====

=== Example 4: Usage in XML Instance

.XML instance using fixed-length list
[example]
====
[source,xml]
----

----

Values are space-separated as per XSD list specification.

== Notes

* Property must have `{sequence}` constraint to be eligible
* Item type is determined from property's value type map entry
* Length restrictions preserve UML multiplicity semantics
* Whitespace handling follows XSD list type specification
* This encoding is more compact than complex type with sequence
