= Rule: rule-xsd-cls-union-as-choice

== Overview

Generates `<xs:choice>` elements for union types instead of sequence elements, allowing exactly one property from the union to be selected.

== Priority

Must-have (used by PLATEAU for union types)

== ShapeChange Documentation

Source:: `/Users/mulgogi/src/external/ShapeChange/shapechange-app/src/docs/asciidoc/targets/xml schema/Non_Standard_Conversion_Rules.adoc`

Description::
Union types represent a choice between multiple options. This rule encodes unions using `<xs:choice>` to reflect this semantic, ensuring only one option can be selected in XML instances.

== Java Implementation

Source:: [`XsdDocument.java:pComplexType`](lines 903-936) and [`XsdDocument.java:pGroup`](lines 1077-1078)

=== Algorithm

The Java implementation follows this process:

. Check if class category is UNION and matches [`rule-xsd-cls-union-as-choice`]
. Validate union hierarchy:
  * If union has no supertype and has properties > 0: Create `<choice>` element
  * If union is subtype of union and both have properties: Report error (incompatible)
  * If union is subtype of union but only supertype has properties: Skip choice (inherit)
. For groups: Apply same `<choice>` generation logic
. Append choice element to the appropriate parent (extension or type)

=== Edge Cases

* **Empty unions**: Unions without properties do not generate a choice
* **Union subtypes**: Subtype unions that don't define properties inherit supertype's choice
* **Conflicting choices**: Union subtype with properties where supertype also has properties generates error

== Test Cases

=== Test Case 1: Simple Union with Choice

Input UML::
[source]
----
«union» GeometryValue
  property pointValue: Point [0..1]
  property lineValue: Line [0..1]
  property polygonValue: Polygon [0..1]
----

Expected XSD::
[source,xml]
----
<complexType name="GeometryValueType">
  <choice>
    <element name="pointValue" type="PointType"/>
    <element name="lineValue" type="LineType"/>
    <element name="polygonValue" type="PolygonType"/>
  </choice>
</complexType>
----

</complexType>
----

== Notes

* Choice elements represent exclusive selection (exactly one option)
* Union inheritance requires careful validation to avoid double-choice scenarios
* Properties of unions become child elements of the choice
* Empty unions (no properties) do not generate choice elements
