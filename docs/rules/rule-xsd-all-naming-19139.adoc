= rule-xsd-all-naming-19139

== Purpose

Applies ISO 19139:2007 naming conventions for types, elements, and property types in XML Schema.

This ensures consistency with ISO 19139 metadata encoding standards.

== Applies To

* All classes (Object, DataType, Feature, CodeList, etc.)
* Type names, element names, property type names

== Algorithm

When this rule is enabled:

1. **Element names**:
   - Abstract classes: Prefix with "Abstract"
   - Concrete classes: Use class name as-is
   ```
   Class: Metadata (abstract) → Element: <prefix:AbstractMetadata>
   Class: Metadata (concrete) → Element: <prefix:Metadata>
   ```

2. **Type names**:
   - Abstract classes: `Abstract{name}_Type`
   - Concrete classes: `{name}_Type`
   - CodeLists: `gco:CodeListValue_Type`
   ```
   Class: Metadata (abstract) → Type: AbstractMetadata_Type
   Class: Metadata (concrete) → Type: Metadata_Type
   Class: RoleCode (codelist) → Type: gco:CodeListValue_Type
   ```

3. **Property type names**:
   - Abstract classes: `Abstract{name}_PropertyType`
   - Concrete classes: `{name}_PropertyType`
   ```
   Class: Metadata (abstract) → PropertyType: AbstractMetadata_PropertyType
   Class: Metadata (concrete) → PropertyType: Metadata_PropertyType
   ```

4. **Substitution groups**: Use `gco:CharacterString` for codelists/enums, `gco:AbstractObject` for others

5. **Base types**: Use `gco:AbstractObject_Type`

== Configuration

No additional parameters required beyond enabling the rule.

== Example Output

For an abstract metadata class:
[source,xml]
----
<xs:element name="AbstractMetadata" type="gmd:AbstractMetadata_Type"
            abstract="true" substitutionGroup="gco:AbstractObject"/>

<xs:complexType name="AbstractMetadata_Type" abstract="true">
  <xs:complexContent>
    <xs:extension base="gco:AbstractObject_Type">
      <xs:sequence>
        <!-- properties -->
      </xs:sequence>
    </xs:extension>
  </xs:complexContent>
</xs:complexType>

<xs:complexType name="AbstractMetadata_PropertyType">
  <xs:sequence minOccurs="0">
    <xs:element ref="gmd:AbstractMetadata"/>
  </xs:sequence>
  <xs:attributeGroup ref="gco:ObjectReference"/>
  <xs:attribute ref="gco:nilReason"/>
</xs:complexType>
----

For a concrete metadata class:
[source,xml]
----
<xs:element name="ResponsibleParty" type="gmd:ResponsibleParty_Type"
            substitutionGroup="gco:AbstractObject"/>

<xs:complexType name="ResponsibleParty_Type">
  <xs:complexContent>
    <xs:extension base="gco:AbstractObject_Type">
      <xs:sequence>
        <!-- properties -->
      </xs:sequence>
    </xs:extension>
  </xs:complexContent>
</xs:complexType>

<xs:complexType name="ResponsibleParty_PropertyType">
  <xs:sequence minOccurs="0">
    <xs:element ref="gmd:ResponsibleParty"/>
  </xs:sequence>
  <xs:attributeGroup ref="gco:ObjectReference"/>
  <xs:attribute ref="gco:nilReason"/>
</xs:complexType>
----

For a codelist:
[source,xml]
----
<xs:element name="RoleCode" type="gco:CodeListValue_Type"
            substitutionGroup="gco:CharacterString"/>
----

== Special Handling

=== CodeLists

CodeLists use special encoding:
- Type: `gco:CodeListValue_Type` (not custom type)
- Element: Standard naming
- Substitution group: `gco:CharacterString`

=== Unions

Union types (category UNION) don't get substitution groups or base types in ISO 19139.

== Notes

- "Abstract" prefix distinguishes abstract types
- Underscore before "Type" suffix (unlike GML/SWE)
- CodeLists reuse `gco:CodeListValue_Type`
- Part of ISO 19139:2007 metadata encoding standard
- Requires `gco` namespace for base types and attributes
- Property types include `gco:ObjectReference` and `gco:nilReason`
