= Rule: rule-xsd-prop-qualified-associations

== Overview

Adds qualifier attributes to association properties, allowing additional metadata to qualify the association relationship in XML Schema.

== Priority

Should-have (used for complex association semantics)

== ShapeChange Documentation

Source:: `/Users/mulgogi/src/external/ShapeChange/shapechange-app/src/docs/asciidoc/targets/xml schema/General_Conversion_Rules.adoc`

Description::
Association properties can have qualifiers that provide additional information about the association. These qualifiers are encoded as XML attributes on the property type.

== Java Implementation

Source:: [`XsdDocument.java:qualifiers, processQualifier`](lines 2458-2544)

=== Algorithm

The Java implementation processes qualifiers as follows:

. Check if property matches [`rule-xsd-prop-qualified-associations`]
. Check if property is not an attribute and is navigable
. Get reverse property (for bidirectional associations)
. If reverse property exists, get its qualifiers
. For each qualifier:
  * Create an attribute element
  * Set attribute name from qualifier name
  * Determine attribute type based on qualifier type:
    ** If qualifier type is mapped: use mapped type
    ** If qualifier type is enumeration: use enumeration type + "Type"
    ** If qualifier type is code list/feature/object: use anyURI
    ** If qualifier type is datatype/union: report error, use string
    ** Otherwise: use string as fallback
  * Add attribute to the property type

=== Type Mapping Logic

[source,java]
----
if (q.type == null) {
    // No type specified, use string
    addAttribute(e1, "type", "string");
} else {
    MapEntry me = options.typeMapEntry(q.type, encodingRule);
    if (me != null && me.p2.equalsIgnoreCase("simple/simple")) {
        // Mapped to simple type
        addAttribute(e1, "type", me.p1);
    } else if (ci.category() == ENUMERATION) {
        // Enumeration type
        addAttribute(e1, "type", ci.qname() + "Type");
    } else if (ci.category() == CODELIST || FEATURE || OBJECT) {
        // Complex types: use URI reference
        addAttribute(e1, "type", "anyURI");
    } else {
        // Unsupported, use string
        addAttribute(e1, "type", "string");
    }
}
----

=== Design Principles

. Process qualifiers from reverse property
. Map qualifier types appropriately
. Use anyURI for complex type references
. Defensive programming for missing types

=== Implementation Details

The [`QualifiedAssociationsProcessor`] class extends [`BaseRuleProcessor`] and:

. Checks if property is association (not attribute)
. Gets reverse property from bidirectional association
. Extracts qualifiers from reverse property
. For each qualifier, creates attribute with appropriate type
. Handles type mapping according to qualifier type category

== Notes

* Qualifiers are read from the **reverse property** of bidirectional associations
* Qualifier attributes are added to the anonymous property type
* Complex types (code lists, features, objects) use anyURI for reference
* If qualifier has no type, defaults to string
* Qualifiers only apply to association properties (not attributes)
* Typically used with byReference encoding
