= rule-xsd-cls-codelist-asDictionary

== Purpose

Encodes code lists represented as GML dictionaries using `gml:CodeType` for GML 3.2 encodings.

== Background

When a code list is represented as a dictionary (rather than as an enumeration in the schema), properties with that code list type need special encoding. This rule ensures that such properties use `gml:CodeType` which provides:

* Element text content for the code value
* Optional `@codeSpace` attribute for the dictionary URI

== Implementation

Based on `XsdDocument.java:mapPropertyType()` lines 3180-3275.

=== Algorithm

When processing a property with a code list value type:

1. Check if the property's class matches this rule
2. Check if the value type is a code list (`category == Options.CODELIST`)
3. Check if code list has `asDictionary()` or `asDictionaryGml33()` flag set
4. Check if the encoding rule for the property's class is GML 3.2 (not GML 3.3)

If all conditions are met:

* Generate property type using `gml:CodeType` as base
* If property has `nilReasonAllowed` or `voidable`, add nilReason attribute support
* If property has metadata, add metadata attribute support
* Add import for `gml` namespace

=== Syntax Definition

[source,ruby]
----
# Property type generation for code list as dictionary
if code_list.as_dictionary? && <1>
   property.in_class.matches?("rule-xsd-cls-codelist-asDictionary") && <2>
   !property.in_class.matches?("rule-xsd-cls-codelist-asDictionaryGml33") <3>

  # Use gml:CodeType as property type
  property_type = "gml:CodeType" <4>

  # Add nilReason support if needed
  if property.nil_reason_allowed? || property.voidable? <5>
    # Create complex type with extension
    create_complex_type_with_extension(property_type) do |extension|
      add_nil_reason_attribute(extension) <6>
    end
  end
end
----
<1> Code list is marked as dictionary
<2> Property's class uses GML 3.2 dictionary encoding
<3> Property's class does NOT use GML 3.3 encoding
<4> Base type is `gml:CodeType`
<5> Check if nilReason support needed
<6> Add nilReason attribute to extension

Where,

`as_dictionary?`:: Returns true if code list is represented as dictionary
`matches?(rule)`:: Checks if encoding rule applies to the class
`gml:CodeType`:: GML 3.2 type with text content and optional `@codeSpace`
`nil_reason_allowed?`:: Property allows nil reason attribute
`voidable?`:: Property is voidable (requires nillable)

== Examples

=== Example 1: Simple Code List Property

.Code list marked as dictionary
[source,ruby]
----
class LandUseCode < Lutaml::Model::Serializable
  attribute :category, :string
  attribute :as_dictionary, :boolean, default: -> { true }
end

class LandUse < Lutaml::Model::Serializable
  attribute :code, LandUseCode
end
----

.Generated XML Schema (GML 3.2 encoding)
[source,xml]
----
<element name="code" type="gml:CodeType" minOccurs="1"/> <!--1-->
----
<1> Simple `gml:CodeType` usage

=== Example 2: With NilReason Support

.Voidable code list property
[source,ruby]
----
class Building < Lutaml::Model::Serializable
  attribute :usage, UsageCode, voidable: true
end
----

.Generated XML Schema
[source,xml]
----
<element name="usage">
  <complexType>
    <simpleContent>
      <extension base="gml:CodeType"> <!--1-->
        <attribute name="nilReason" type="gml:NilReasonType"/> <!--2-->
      </extension>
    </simpleContent>
  </complexType>
</element>
----
<1> Extends `gml:CodeType`
<2> Adds nilReason attribute support

=== Example 3: Instance Usage

.XML instance using code list as dictionary
[source,xml]
----
<LandUse>
  <code codeSpace="http://example.org/codelists/landuse"> <!--1-->
    residential <!--2-->
  </code>
</LandUse>
----
<1> Code space points to dictionary
<2> Code value in text content

== Configuration

=== When This Rule Applies

* Code list has `asDictionary` or `asDictionaryGml33` flag set
* Property's containing class matches `rule-xsd-cls-codelist-asDictionary`
* Property's containing class does NOT match `rule-xsd-cls-codelist-asDictionaryGml33`
* Encoding is GML 3.2 (not GML 3.3)

=== Related Rules

* `rule-xsd-cls-codelist-asDictionaryGml33`: GML 3.3 variant (uses `gml:ReferenceType`)
* `rule-xsd-cls-codelist-gmlsf`: GMLSF variant (fixed codeSpace)
* `rule-xsd-prop-nillable`: Adds nillable support
