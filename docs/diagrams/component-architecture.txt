Data Flow Between Components
==============================

User Input (CLI)
    │
    ▼
Command Object
    │
    ├─→ Load Type Overrides (YAML)
    ├─→ Parse Config (XML via moxml)
    ├─→ Parse XMI (via lutaml-xmi)
    └─→ Parse XSD files (via moxml)
    │
    ▼
MappingGenerator.new(
  config: config,
  xmi_navigator: navigator,
  xsd_analyzers: analyzers,
  type_overrides: overrides
)
    │
    ▼
For each UML Package:
    │
    ├─→ Extract UML Classes
    │   │
    │   └─→ For each Class:
    │       │
    │       ├─→ Find matching XSD Type
    │       │
    │       └─→ For each Attribute:
    │           │
    │           ├─→ Apply Type Override (if configured)
    │           ├─→ Resolve via ShapeChange mapping
    │           ├─→ Resolve namespace
    │           └─→ Create AttributeMapping
    │
    ▼
SchemaMapping (YAML Output)


Component Responsibilities
==========================

CLI Layer:
- Parse command-line arguments
- Validate user inputs
- Display help and errors
- Coordinate command execution

Command Layer:
- Implement specific commands
- Load and validate inputs
- Coordinate processing components
- Handle errors and output

Orchestration Layer:
- Coordinate multi-source mapping
- Apply transformation rules
- Manage type resolution
- Build output structures

Processing Layer:
- Parse input formats (XMI, XML, XSD)
- Navigate data structures
- Extract relevant information
- Build internal models

Model Layer:
- Represent UML structures
- Represent XSD structures
- Represent configuration
- Represent mappings (output)

Integration Layer:
- Interface with external gems
- Provide consistent APIs
- Handle format conversions
- Delegate specialized operations
