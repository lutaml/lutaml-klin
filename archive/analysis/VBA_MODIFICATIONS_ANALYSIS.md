# VBA Modifications Analysis

## Overview

This document analyzes the modifications made by the Excel VBA program `XSD整形_2024年度用.xlsm` to PLATEAU XSD files generated by ShapeChange 3.1.0.

## Summary

- **Files Modified**: 1 out of 119 XSD files (`urbanObject.xsd` only)
- **Lines Added**: 101 lines (99 element declarations + 2 comment markers)
- **Elements Added**: 99 global element declarations
- **Purpose**: Add GML application property extension points for URO attributes

## VBA Modification Pattern

The VBA program inserts a block of global element declarations between two comment markers:

```xml
<!-- =================== 整形プログラムによる「_GenericApplicationPropertyOf」関係の追記　↓　 ================ -->
<!-- Translation: "Additions by formatting program for _GenericApplicationPropertyOf" -->

[99 element declarations here]

<!-- =================== 整形プログラムによる「_GenericApplicationPropertyOf」関係の追記　↑　 ================ -->
```

## Element Declaration Pattern

Each added element follows this pattern:

```xml
<xs:element name="{attributeName}"
            type="uro:{TypeName}"
            substitutionGroup="{namespace}:_GenericApplicationPropertyOf{ClassName}"/>
```

### Examples

```xml
<xs:element name="bldgDataQualityAttribute"
            type="uro:DataQualityAttributePropertyType"
            substitutionGroup="bldg:_GenericApplicationPropertyOfAbstractBuilding"/>

<xs:element name="ifcBuildingAttribute"
            type="uro:IfcAttributePropertyType"
            substitutionGroup="bldg:_GenericApplicationPropertyOfAbstractBuilding"/>

<xs:element name="buildingDetailAttribute"
            type="uro:BuildingDetailAttributePropertyType"

```

## Why These Were Added

### Purpose

The VBA program adds these global element declarations to enable URO (Urban Object) attributes to be used as **GML Application Properties**. This is a CityGML/GML3 extension mechanism.

### GML Application Property Pattern

In GML/CityGML, application properties allow extending base schemas with domain-specific attributes through substitution groups. The pattern is:

1. Base schema defines abstract extension points like `_GenericApplicationPropertyOfAbstractBuilding`
2. Application schemas declare concrete elements that substitute for these extension points
3. Instance documents can include these elements as children of the extended class

### Example Usage in Instance Documents

```xml
<bldg:Building>
  <bldg:lod1Solid>...</bldg:lod1Solid>
  <!-- VBA-added extension point enables this: -->
  <uro:bldgDataQualityAttribute>
    <uro:DataQualityAttribute>
      <uro:srcScale>2500</uro:srcScale>
      <uro:geometrySrcDesc>数値地形図データ</uro:geometrySrcDesc>
    </uro:DataQualityAttribute>
  </uro:bldgDataQualityAttribute>
</bldg:Building>
```

## Impact on ShapeChange Parity

### What ShapeChange 3.1.0 Actually Generates

ShapeChange does **not** generate these global element declarations. It only generates:

1. Complex types for URO attributes
2. Property types for URO attributes
3. Local elements within URO classes

### What lutaml-klin Should Generate

For **true** ShapeChange 3.1.0 parity, lutaml-klin should match the **unmodified** output, which means:

- ✅ Generate all complex types and property types
- ✅ Generate local elements within classes
- ❌ Do NOT generate global substitution group elements (these are VBA additions)
